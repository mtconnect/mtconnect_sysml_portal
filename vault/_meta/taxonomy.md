# Taxonomy

> Controlled vocabulary for `tags:` in page frontmatter. Add a tag here before using it in a page.

## Domain tags

One entry per `wiki/<domain>/` folder, plus secondary domain tags used for cross-cutting topics.

### Primary domains

- `portal` — the MTConnect SysML Portal as a whole (`wiki/portal/`)
- `json-schema` — JSON Schema generation and artifacts (`wiki/json-schema/`)
- `generators` — the Ruby generator framework that produces all derived artifacts (`wiki/generators/`)
- `ci-cd` — build, deploy, and GitHub Actions workflow (`wiki/ci-cd/`)

### Secondary / cross-cutting

- `xml-schema` — XSD 1.0 / 1.1 schemas emitted by the schema generator
- `owl` — OWL/Turtle ontology emitted by the OWL generator
- `pdf` — PDF documentation generated by the LaTeX pipeline (deprecated path)
- `jekyll` — Jekyll static-site build and `just-the-docs` theme
- `sysml` — SysML/XMI source model (Cameo / MagicDraw)
- `versioning` — release versions, version channels, and `build.yml`
- `validation` — the validation generator and validation suite

## Type tags

Pick at least one per page.

- `architecture-decision` — a choice was made and the rationale matters
- `how-to` — actionable guide
- `reference` — descriptive background, not a decision
- `implementation` — describes code or a system being built
- `research` — exploratory, not yet a decision
- `meta` — about the vault itself (`_about.md` files)

## Status tags

Exactly one per page.

- `active` — work is ongoing or the content is current
- `resolved` — done; no further work expected
- `deprecated` — superseded by a newer page; kept for history

## How to extend

1. Open a PR that updates this file with the new tag and a one-line description.
2. In the same PR, use the tag in the page that needed it.
3. Reviewers check that the new tag is genuinely needed and not a synonym for an existing one.
